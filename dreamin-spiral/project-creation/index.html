Project Creation

技術のことは分かる。
でも、Project全体を見ようとすると、
急に難しくなる。

顧客が本当に求めていること。
Businessとして何を目指しているのか。
チームで何を決め、どう前へ進めるのか。

エンジニアとして積み重ねてきたものを土台に、
人・Business・Projectへ、
少しずつ視野を広げていきます。

エンジニアから、プロジェクトを創る人へ。

Project Creationについて見てみる ↓

こんなことを、
感じることはありませんか。

エンジニアとして仕事をしてきた。

技術について考え、
問題を解き、
ものを創ることには慣れてきた。

でも最近、

  • 「もう少しProject全体を見てみたい」
  • 「顧客やBusinessにも関わってみたい」
  • 「自分で全部解くのではなく、チームで何かを創る仕事をしてみたい」

そんな感覚が、どこかにある。

一方で、
“管理職になる”と言われると、少し違う。

PMになって進捗管理ばかりするのも、
自分がやりたいこととは違う気がする。

無理に「管理職らしく」なる必要はありません。
誰かのPM像に、自分を合わせる必要もありません。

もし、そんな感覚があるなら、
Project Creationは、ひとつの次の可能性かもしれません。

PMになることと、
Projectを創れるようになることは、同じではありません。

Projectを前に進めるために必要なのは、

進捗表を更新することだけでも、
会議を増やすことでも、
メンバーを管理することでもありません。

必要なのは、

  • 何が起きているのかを観ること。
  • 人の言葉を受け取ること。
  • Intentを捉えること。
  • 複雑な状況を構造化すること。
  • 必要な問いを置くこと。
  • 意思決定を生み出すこと。
  • 次の行動へつなげること。

Project Creationは、
役職としてPMになるためだけの講座ではありません。

役職名よりも、
Projectが動ける状態を創ることを扱います。

Projectの見方が、
少しずつ変わっていく。

今まで身につけてきた技術も、
考える力も、
問題を解いてきた経験も、
そのまま次の土台になります。

Before

自分で考える。
自分で解決する。
自分で答えを出そうとする。

Shift

状況を観る。
人の言葉を受け取る。
Intentを捉える。
構造化する。
問いを置く。
人と答えを創る。
意思決定を生み出す。

自分で答えを抱え込むエンジニアから、
人と問いを交わしながら、
チームで答えを創れる人へ。

Projectを動かすための、新しい仕事のOS

  1. Observe起きていることを観る
  2. Receive人・事実・数字・違和感を受け取る
  3. Intentその奥にある目的や意図を見る
  4. Structure複雑な状況を構造化する
  5. Ask必要な問いを置く
  6. Decide意思決定を生み出す
  7. Natural Doing次の行動へつなげる

PM / PdM / PMOを、
ひとつのProjectから見る

PM
Projectを成立させ、前へ進める。
PdM
何を、なぜ創るのかを考える。
PMO
Projectが動きやすい環境を創る。

3つは、選ぶコースではなく、ひとつのProjectを見るための視点です。
最初からどれか一つを選ぶ必要はありません。

PM経験がなくても参加できますか？
参加できます。

最初から1つに決める必要はありません。

参加できます。
